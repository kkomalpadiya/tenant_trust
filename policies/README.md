# Policy source

OPA loads reviewed Rego policy and prototype tenant data from this directory in local development. The bootstrap package still provides a deterministic readiness query. `authorization/decision.rego` is the fail-closed access decision at `tenant_trust/authorization/decision`; root `data.json` supplies the local tenant's score/sensitivity configuration and deployment provenance.

The application-side RBAC eligibility and sensitivity contract is defined in `packages/authorization`; it does not replace an OPA decision and treats operations that require later controls as non-allowing. The versioned Data API request and response contract is defined in `packages/contracts/schemas/policy` and documented in `docs/architecture/opa-decision-contract.md`.

Tenant bundle publication and activation are defined in `services/policy` and documented in `docs/architecture/tenant-policy-bundle-versioning.md`. A bundle must use `tenant_trust/authorization/decision`, remain tenant-scoped, compile as Rego v1 with the pinned OPA version and carry immutable content/version provenance. PostgreSQL is the active-version authority; the API rejects a decision whose policy ID, version, digest or path differs from that tenant's active row. Application callers use only the Data API decision path and do not modify policy through OPA management APIs.

Run `npm run policy:test` for all checked-in Rego tests, `npm run policy-bundles:verify` for bundle validation/lifecycle/provenance enforcement, `npm run adaptive-policy:verify` for the complete T7.4 gate, `npm run step-up-authentication:verify` for bound proof enforcement and `npm run policy-outcomes:verify` for DENY/QUARANTINE enforcement. The local `slide-14-prototype-v1` values are deliberately labelled `unvalidated-prototype-defaults`; they are tenant configuration, not production-wide constants. Quarantine decisions now emit durable action requests; executing those requests remains separate orchestration work.
