# Tenant Trust API

This workspace exposes the first certificate-authenticated SaaS endpoints:

- `GET /v1/profile` returns the authenticated subject's tenant profile.
- `GET /v1/tenant-records` returns records visible to the authenticated actor.
- `GET /v1/tenant-records/:recordId` returns one visible record or the uniform `403 ACCESS_DENIED` response.
- `POST /v1/tenant-records/export` returns an all-or-nothing export of 1–25 visible records after tenant-admin eligibility and a trusted internal control decision.
- `POST /v1/admin/membership-reviews` returns one same-tenant membership review after the same fail-closed sensitive-operation boundary.
- `POST /v1/evidence` accepts a contract-valid, size-bounded envelope only after exact tenant/source/key/subject binding plus canonical SHA-256 and Ed25519 verification. Configure `evidenceIngestionService` to register this source-authenticated route.

Construct the application with `createTenantTrustApi`, a request authenticator created from the gateway identity resolver, `createPostgresTenantRepository`, and `createPostgresRequestAuditRecorder`. Repository construction requires the branded mode returned by `selectAuthorizationMode("pki-rbac-baseline-v1")`. It exposes the fixed `authoritative-per-request-state-v1` and `stateless-mtls-replay-guard-v1` policies, while the recorder exposes the fixed `append-only-request-outcomes-v1` policy; the API verifies all four declarations before registering routes. The API never accepts a tenant, authorization mode, request ID or correlation ID selector in a route, query, body or header. Its gateway adapter passes only the raw internal TLS socket and headers to `@tenant-trust/gateway-identity`; identity and tenant headers outside that resolver are not authority. Protected requests are stateless: ambient `Cookie` and `Authorization` headers are rejected, and responses carry no-store directives.

Every repository operation starts a PostgreSQL transaction, assumes the `tenant_trust_app` privilege set locally, binds the authenticated tenant and subject with `identity.set_tenant_actor_context`, loads authoritative tenant/membership/role state, resolves the immutable tenant context, and matches the gateway certificate to fresh PostgreSQL inventory state. The five-second request-state deadline is checked again immediately before each protected query. The same five-second request deadline is backed by abort-aware repository calls, a four-second PostgreSQL statement timeout and a one-second lock timeout; timeout rolls the transaction back and returns fail closed. No allow is cached across requests. The explicit PKI/RBAC baseline then evaluates the exact action, and an ordinary allow reaches a query with an explicit tenant predicate. Forced row-level security separately enforces tenant, ownership, administrator, and current membership rules. Baseline decisions contain no trust or evidence input.

Human certificate-authenticated request bodies are limited to 4 KiB. Extra fields and query controls are rejected rather than stripped, and callers cannot provide tenant, role, sensitivity, authorization results, mode or operation IDs. Sensitive routes require `Idempotency-Key: idem_<UUID>` and default to denial unless the repository receives a trusted `sensitiveOperationAuthorizer`; even that callback is reached only after the baseline returns `requires-controls` for an authoritative tenant-admin matrix row. A tenant/actor/action-scoped PostgreSQL receipt stores only the key and normalized-request hashes plus a server-generated `op_<UUID>`. Identical retries reuse that operation ID and mark `idempotentReplay`; conflicting reuse returns `409 IDEMPOTENCY_CONFLICT`.

The evidence route is a separate source-authenticated boundary with a 64 KiB raw-envelope limit and a 32 KiB canonical-payload limit. It does not accept tenant or subject authority from transport headers, does not invoke the human mTLS resolver and returns only a bounded receipt. Schema failures return `400 INVALID_REQUEST`, size failures return `413 REQUEST_TOO_LARGE`, and all valid-shape source, binding, digest or signature denials return the same `422 EVIDENCE_REJECTED` response. A successful response is returned only after the canonical signed envelope has been application-encrypted and stored atomically with its accepted replay receipt.

Each schema-valid protected request receives server-generated `req_<UUID>` and `cor_<UUID>` values returned as `X-Request-ID` and `X-Correlation-ID`. The API records an authentication outcome before repository access and an access outcome before returning the result. Events contain trusted actor/tenant identity, the fixed action and route, resource type, a SHA-256 resource-identifier hash, the decision/reason, selected mode and optional operation ID. The exact event shape has no header, query, body, payload, certificate, cookie or response field. Failed authentication records null actor/tenant rather than trusting claimed identity. Audit capture failure returns `503 SERVICE_UNAVAILABLE`; it never releases an unaudited allow.

Run unit coverage with `npm run test:api`. With the migrated and provisioned local PostgreSQL service running, use `npm run profile-record-api:verify` for the live Alpha/Beta profile, ownership, administrator, guessed-record, and forged-header cases, `npm run sensitive-operations:verify` for the bounded export, membership-review, default-deny and operation-ID cases, `npm run pki-rbac-baseline:verify` for explicit Baseline B selection and no-adaptive-trust behavior, `npm run request-state:verify` for revoked-certificate, tenant-suspension, membership-suspension and connection-reuse cases, `npm run request-outcomes:verify` for append-only outcome capture, correlation and data minimization, and `npm run request-safeguards:verify` for session rejection, replay/conflict, size limits and timeout rollback.

Record writes, adaptive authorization and state-changing administration remain outside this task's scope. Later audit phases will canonicalize selected off-chain rows and deliver commitments to Fabric; the current recorder does not claim a ledger commitment.
